# 前端完善路线图

> 状态：规划基线（2026-11-23；已纳入管理端体验反馈）

## 目标与设计原则

目标是把 GKD Subscription Hub 做成完整的平台管理端（Full Platform），采用专业、统一的管理界面（Professional UI），而不是只堆叠独立功能页。

- 先建立统一的类型、API 访问层和 AdminLayout，再扩展业务页面。
- 延续 Vue 3 + Vite + Naive UI；使用 Bun workspaces 与 bun.lock 管理工作区，使用 Biome 进行代码质量检查。
- 以 `zclzone/vue-naive-admin` 的成熟管理端结构作为可裁剪参考/基础，不为套模板而重写已有业务。
- 视觉方向采用 Fluent-inspired；单一 CSS Design Tokens 是唯一设计源，Naive UI 主题和业务 CSS 均映射到 Tokens，禁止另起一套硬编码视觉规范。
- 管理端默认中文；只有项目整体协作氛围明确以英语为主时才使用英语。
- 面向订阅客户端的响应优先保证原始订阅内容；浏览器访问再提供友好预览。

### P1：规则发现正确性与扫描模型

- [ ] **EXP-01 扫描流程分阶段**：维护者希望先尽可能收集候选，再逐级筛选/验证。当前 Worker 仅在候选缓冲区为空时读取下一页 GitHub 搜索结果。读取后，每个 step 最多验证缓冲区中的 4 个候选。候选超过 4 个时，同一页需要多个 step 才能验证完成，之后才读取下一页。因此进度按页分段呈现，页内按候选分批推进。评估改为逻辑上的两阶段流水线：先在有界批次内收集/去重候选摘要，再分批验证仓库和订阅文件。不能承诺无上限“全量拉取”：GitHub Search 单查询最多 1,000 条；GitLab/Gitea 的搜索能力、分页上限与配额由各 Provider adapter 分别声明，Worker CPU/subrequest、KV 单值大小和 API 配额也要求分批。UI 应分别展示候选收集与内容验证进度，并说明未覆盖边界。
- [ ] **EXP-02 ID 233 / 搜索结果异常**：维护者观察到仓库目录后段出现大量 ID 233，怀疑筛选不足。当前全文搜索使用子串匹配，并把订阅 ID、仓库名、描述、作者、Topic、自定义字段混合搜索；当前后端按 GitHub repository ID 去重；Provider 化后按 provider、实例和平台不可变仓库 ID 组合去重（Provider 化后应按 `provider + instance + immutable repository ID` 去重），但未对不同仓库的订阅 ID 重复作冲突提示。需用实际查询词和目录快照复现，核对原始订阅文件、仓库 ID、订阅 ID、分页去重和 UI row-key。增加独立的精确订阅 ID 筛选/匹配模式、重复 ID 诊断和数据来源提示；在复现前不认定为分页 Bug。
- [ ] **EXP-03 搜索可解释性**：搜索结果说明命中字段，提供精确 ID、仓库名/Owner、订阅名称/作者等结构化筛选；避免把模糊子串匹配伪装成精确 ID 查询。
- [ ] **EXP-04 扫描可靠性测试**：覆盖多页收集、跨查询去重、重复订阅 ID、候选为空、Search 结果 incomplete、限流暂停/恢复、目录快照原子发布及中途失败不覆盖上次完整目录。

### 本轮已由源码确认的事实

1. 登录页当前 placeholder 为 `输入 ADMIN_PASSWORD`。
2. `AdminLayout.vue` 当前源码中桌面侧栏在主内容之前，移动端使用左侧 Drawer；线上显示位置异常仍待复现。
3. 项目新增表单当前使用自由文本 `NInput` 填写分支。
4. 注册服务当前只接受 GitHub URL，扫描和分发依赖 GitHub API/Raw。
5. 项目表格当前把 `ID` 放在仓库名单元格首行；源码入口没有独立动作。
6. JSON5 浏览器预览当前输出转义后的原始文本，无格式化/高亮/树形视图。
7. Explorer 当前按搜索页逐页收集并验证；每次 step 最多验证 4 个候选，Code Search 每个查询只请求第一页。
8. Explorer 全文搜索是跨字段子串匹配；按 GitHub repository ID 去重，不检查订阅 ID 冲突。

以上是源码审计事实，不等于对线上截图/实际数据的复现结论。

## 执行约定

1. 每个阶段拆成可独立评审的 PR，不把所有 UI 改造塞进一个大 PR。
2. 先做基础架构和壳层，再推进页面；避免并行制造重复布局。
3. 每个 PR 同步更新相关文档和必要测试。
4. 不以“CI 通过”代替功能验收；涉及浏览器交互的功能必须验证实际页面行为。
5. 不执行真实生产扫描或写入生产数据作为普通 UI Smoke Test。
