# 文档规范

## 文档分层

- **README**：面向使用者、评估者和贡献者，回答项目用途、能力、快速开始、部署和求助方式。
- **CONTRIBUTING**：面向贡献者和 Agent，说明开发、测试和 PR 流程。
- **AGENTS.md**：面向所有编码代理，说明仓库事实、硬约束、命令和完成定义。
- **CLAUDE.md**：Claude Code 加载入口和专属约定。
- **docs/engineering**：维护者使用的工程标准、审计、文档和 Agent 体系。
- **领域设计文档**：领域模型、流程、API 和失败模式。
- **docs/adr**：记录架构决策及被放弃的方案。
- **Roadmap**：记录计划、优先级、状态和验收。

## README 规则

1. 一句话说明用途和目标用户。
2. 核心能力只写当前实现，规划项明确标记。
3. 提供最短 Quick Start：环境、安装、开发、测试。
4. 部署只描述当前有效流程；复杂设置链接到独立文档。
5. API/配置表格说明必填、默认值和敏感性。
6. 显式说明限制、已知风险和安全边界。
7. 链接使用仓库相对路径，确保 fork 与本地 clone 可用。
8. 不复制完整架构设计、长日志或过期截图。
9. 每次改动核对链接、命令、功能状态。
10. 默认中文；目标用户或上游生态明确以英语为主时可用英语。

## 领域设计文档

应说明状态（Draft/Proposed/Accepted/Superseded）、背景目标、非目标、领域模型、数据流、API、错误/重试/并发/安全边界、成本/配额、验收和未验证假设。只对跨模块、持久化或安全边界复杂的功能建立文档。

## ADR

建议目录 docs/adr/，文件名 NNNN-short-title.md，编号递增不复用。

```markdown
# ADR-NNNN: 标题

- 状态：Proposed
- 日期：YYYY-MM-DD

## 背景

## 决策

## 备选方案

## 影响与代价

## 安全 / 性能 / 运维

## 回滚与迁移
```

只记录影响多个模块、长期成本、安全边界、数据结构或部署拓扑的决策。被替代时保留原 ADR 并标记 Superseded。

## Roadmap 状态

- [x]：目标分支已确认实现；运行时行为需有测试/验收证据。
- [ ]：未实现。
- [~]：进行中，附 PR/Issue。
- 已实现不等于已验收；浏览器手动验证单独记录。
- 每阶段说明目标、范围、非目标、验收标准和退出条件。

## 变更同步矩阵

- **用户可见功能**：README、路线图。
- **API/请求响应**：设计文档、README API、Admin/Worker 类型与测试。
- **环境变量/Secrets**：README、CI/CD、dev vars 示例、部署配置。
- **部署/Preview**：README、CI/CD、AGENTS/CLAUDE。
- **架构/技术选型**：工程标准、架构概览；重大决策写 ADR。
- **测试/质量门禁**：AGENTS、README 命令、CI。
- **Agent 协作**：AGENTS、CLAUDE、Agent 工作流。
- **内部重构**：审查架构文档是否仍准确。

## 文档检查

检查相对链接、命令、路径大小写、Secret/个人信息、功能状态、版本号、部署平台和环境变量是否与代码一致。
