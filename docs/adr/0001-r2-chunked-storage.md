# ADR 0001：Cloudflare R2 统一分块存储

- 状态：已接受（仅确认存储范围；具体实现待设计）
- 日期：2026-11-26
- 决策范围：GKD Subscription Hub 所有写入 Cloudflare R2 的文件

## 背景

当前历史订阅归档使用 D1 保存版本/对象元数据、R2 保存 Gzip 压缩后的完整文件对象，并通过 SHA-256 对完全相同的文件去重。该方式无法有效复用两个不同版本之间未变化的内容；跨订阅的重复内容也只能在整文件字节完全相同时去重。

项目存在多个订阅源及上游仓库传承关系。仅按仓库或整文件归档会造成重复存储；但不能仅凭 Fork 关系或规则语义相似就认定内容相同。

## 决策

**所有存入 Cloudflare R2 的文件统一采用分块存储。**

- 不限于历史 JSON5 订阅快照，也不按文件大小设置绕过分块的例外。
- R2 存储内容寻址的数据块；相同内容块可跨版本、订阅和文件复用。
- D1 保存文件 Manifest、块顺序、文件元数据及引用关系。
- Worker 负责切块、压缩、写入、校验、Manifest 登记，以及读取时的块获取、解压和按序重组。
- 对外读取仍返回原始文件字节；内部块布局不得改变既有文件 URL 或客户端协议。
- 去重依据必须是实际内容身份（例如经验证的哈希）；Fork / 传承关系只用于来源追踪，不能作为内容相同的证明。

## 一致性与安全要求

1. 重组后的字节必须与写入前原始文件逐字节一致。
2. 读取完成后校验原始长度与整体 SHA-256；必要时也校验单块哈希。
3. 缺块、损坏、超时或校验失败必须明确失败，不得返回部分文件，也不得回退到 latest。
4. Manifest 与块引用的登记/释放必须幂等，并正确处理并发写入和删除。
5. GC 不得删除仍被任何有效 Manifest 引用的块；永久删除遵循管理员权限与保留策略。
6. R2 Bucket 继续保持私有，不配置绕过应用策略的生命周期自动删除。

## D1 与 R2 的职责边界

- **R2**：唯一内容块的持久化对象存储。
- **D1**：文件/版本元数据、Manifest、Chunk 元数据、引用关系、归档任务、预算与 GC 状态。
- **Worker**：切块/压缩/寻址/校验/重组的统一存储服务。
- **调用方**：继续使用稳定文件 URL，不感知分块。

D1 不会因采用分块而失去用途；它仍然是业务索引、Manifest 与生命周期状态的权威数据源。

## 尚未决策（必须 PoC / 评估后再定）

- 分块算法：FastCDC、固定大小分块或其他方案。
- 块大小分布、最小/最大块大小和小文件处理方式。
- 压缩算法与级别（Gzip、Zstandard 等），是否按块独立压缩。
- 哈希算法、对象 Key 版本、Manifest 序列化与版本迁移。
- D1 表结构、事务边界、引用计数或可替代的引用追踪方案。
- 上传并发、幂等、重试、部分失败清理和归档任务恢复。
- 读取时批量请求、缓存策略、R2 请求费用与 Workers CPU/内存。
- 软删除保留期、压力阈值、GC 触发策略、管理员永久删除审计。
- 当前完整对象到分块对象的迁移策略及回滚方式。
- Git 历史/Packfile 是否保留为来源证据或 PoC 对比方案。

## 验证计划

用真实订阅历史与跨仓库样本比较完整快照压缩、Git Packfile、内容寻址分块等候选实现。至少记录：

- 原始总字节数、压缩后物理存储量、跨项目去重率。
- R2 对象数量、PUT/GET 请求数、恢复延迟。
- Worker CPU/内存、D1 查询/写入量。
- 块缺失/损坏恢复、并发写入、GC 与迁移测试。
- 在 Cloudflare Free 预算下的实际成本与维护复杂度。

## 后果

### 正面

- 同一文件的不同版本可以复用未变化内容。
- 跨订阅、跨项目的相同内容块可复用，避免依赖仓库关系推测重复。
- 统一 R2 存储层，后续新增文件类型无需重复设计归档系统。

### 代价

- 读取需要 Manifest 查询、多个块对象读取和重组。
- 需要可靠处理 Manifest、引用关系、GC、并发和迁移，复杂度高于完整对象存储。
- 必须通过真实数据 PoC 证明空间收益足以覆盖额外请求、CPU 与维护成本。

## 实施状态

本 ADR 只锁定“所有 R2 文件采用分块存储”的范围决策。当前生产代码仍采用完整文件 Gzip 对象；在实现和迁移完成前，不得宣称分块存储已上线。
